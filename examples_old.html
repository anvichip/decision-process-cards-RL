What does the improvement support?

Five Decision Process Cards. Different decision processes. A shared way to describe what changed, what evidence it needs, and how far the claim can go.

01Specify the process

Read the state, actions, feedback, support, and update mechanism together.

02Check the evidence

Reporting prompts identify details needed from the particular study.

03Bound the claim

A missing field matters when a stronger claim depends on it.

01

DPO

Direct Preference Optimization

Fit a response policy to fixed pairwise preferences under reference-policy and data-support assumptions.

Fixed-data preference fitting

Supported claim scope

Fixed-data preference alignment under comparison-data and support assumptions.

Stronger claims need more evidence

Exploration, online control, or safe deployment adaptation.

Claim tier
Response / preference alignment.The manuscript classifies standard DPO as fixed-data preference optimization derived from regularized RL.
State or belief
Prompt-conditioned responses.Report the prompt representation and any additional conditioning.
Action granularity and horizon
Full response as the reported decision unit.Report tokenization and horizon conventions where they affect the claim.
Reward and cost
Pairwise preferences and a fixed-data log-ratio loss.Report label provenance, judge validity, and any cost channels; costs are not specified here.
Prompt/task support
Fixed comparison data.Report prompt distribution, task strata, behavior-policy provenance, and domain coverage.
Response/trajectory support
Chosen and rejected response alternatives.Report coverage and support limits; broad prompt coverage does not establish response coverage.
Value and uncertainty
Not specified in the worked example.Report reward or judge uncertainty and calibration if the claim relies on them.
Model interface
Reference policy; no world model required for this tier.No transition-model or planning claim is supplied by this example.
Adaptation surface
Policy fitting during training.Distinguish training updates from deployment adaptation. Continual updates and rollback are outside this worked claim.

Priority evidence checks

  • Preference provenance and reference policy
  • Behavior distribution and rejected alternatives
  • Judge validity and reward overoptimization checks
Manuscript basis: Worked DPC claim ceilings; contextual-bandit discussion.
Citation keys: rafailov2023dpo; azar2023general
02

PPO-RLHF

Completion-level reward-model optimization

Optimize completion rewards while distinguishing reference-policy regularization from update stabilization.

Reward-driven policy optimization

Supported claim scope

Response-level reward-driven policy optimization under the stated prompt, reward-model, and support assumptions.

Stronger claims need more evidence

Long-horizon control, a safety guarantee, or safe continual adaptation from reward gains or KL alone.

Claim tier
Response / preference alignment.This card covers completion-only PPO-RLHF, not every system that uses PPO.
State or belief
Prompt and generated prefix.The manuscript defines token state as the prompt plus preceding tokens.
Action granularity and horizon
Token generation; whole-response abstraction under stated conditions.A bandit interpretation requires independent prompts, terminal scoring, between-episode updates, and no within-episode external side effects.
Reward and cost
Learned reward and fixed-reference KL regularization.Report reward provenance and validity. Reference KL and PPO update stabilization have different roles; neither supplies a safety guarantee.
Prompt/task support
Training prompt distribution.Report task and user coverage and how update data are collected.
Response/trajectory support
Policy-generated completions and base-policy support.Report sampling and reachability diagnostics; the method name alone does not establish coverage.
Value and uncertainty
PPO critic / value estimation.Report the critic target and calibration where relevant; reward uncertainty is a separate reporting question.
Model interface
Known token concatenation and a reward model.A learned external transition model is not required for completion-only claims.
Adaptation surface
Policy updates between episodes in the stated reduction.If the reward model changes, report versions, refreshed data, and drift checks. Deployment updates require further evidence.

Priority evidence checks

  • Reward-model validity and versioning
  • Fixed-reference KL versus old-policy update control
  • Prompt independence and absence of within-episode tool or memory effects
Manuscript basis: When completion RLHF is a contextual bandit; DPC tiers.
Citation keys: ziegler2019fine; stiennon2020learning; ouyang2022training; schulman2017ppo
03

GRPO

Verifier-reward optimization for math

Improve verifier reward using groups of sampled solutions and group-relative advantages.

RL with verifiable rewards

Supported claim scope

Verifier-reward policy improvement for covered math tasks.

Stronger claims need more evidence

Broad reasoning capacity, competence under shifted verifiers, or deployed agentic control.

Claim tier
RL with verifiable rewards.This card follows the manuscript's GRPO math example.
State or belief
Math prompt and generated solution prefix.Report the task representation; no external agent state is specified in this example.
Action granularity and horizon
Sampled solutions grouped by prompt.Report token / response granularity, generation limits, and the horizon convention.
Reward and cost
Verifier rewards, group-relative advantages, and reference regularization.Report verifier false-positive and false-negative risks, reward normalization, and any cost channels.
Prompt/task support
Covered math prompt distribution.Report task-family strata and verifier coverage before making broader transfer claims.
Response/trajectory support
Base-policy solution reachability.Report pass@k or likelihood-based support and how group sampling changes observed coverage.
Value and uncertainty
Group-relative advantages reduce reliance on critic estimation.They do not establish calibrated verifier uncertainty or remove credit-assignment questions.
Model interface
Verifier interface for generated solutions.This example supplies no learned environment-model or model-based control claim.
Adaptation surface
Policy improvement through training updates.Report entropy and length dynamics; deployment adaptation and rollback need separate evidence.

Priority evidence checks

  • Verifier definition, coverage, and error risks
  • Base-policy pass@k or reachability
  • Reward normalization, entropy, length, and sampling dynamics
Manuscript basis: Worked DPC claim ceilings; DPC tiers; evidence audit.
Citation keys: shao2024deepseekmath
04

Agent Lightning

Agent training from interaction traces

Train agent policies from interaction data through a reward service and credit-assignment interface.

Tool / memory agent RL

Supported claim scope

Trace-level agent policy improvement in the specified environments.

Stronger claims need more evidence

Deployed persistent control without cost, versioning, replay, uncertainty, and rollback evidence.

Claim tier
Tool / memory agent RL.A deployed/adaptive claim requires additional fields beyond this training example.
State or belief
Agent observations, actions, and interaction histories.Report external environment state and the observation or belief representation actually used.
Action granularity and horizon
Agent actions within interaction traces.Report tool/action schemas, hierarchy, temporal granularity, termination, and horizon.
Reward and cost
Reward service and credit-assignment interface.Report reward sources, intermediate-credit semantics, side effects, and cumulative costs.
Prompt/task support
Specified training and evaluation environments.Report task coverage, environment versions, and data-collection policies.
Response/trajectory support
Interaction traces used to train agent policies.Report trajectory coverage, off-policy reuse, unsupported actions, reset assumptions, and replay semantics.
Value and uncertainty
Not specified in the manuscript's worked row.Report value targets, uncertainty, and calibration when the claim requires them.
Model interface
Agent / environment interaction interface.Do not infer a learned world model from the framework name; report any planning or model interface separately.
Adaptation surface
Agent-policy training from interaction data.Distinguish policy updates, tool state, and memory changes. Persistent deployment claims need thresholds, privacy boundaries, drift checks, and rollback.

Priority evidence checks

  • Observation/action schemas and trace support
  • Environment versions, resets, and replay assumptions
  • Side effects, cumulative costs, and deployment rollback where claimed
Manuscript basis: Worked DPC claim ceilings; tool/memory DPC requirements.
Citation keys: luo2025agentlightning
05

Reflexion

Memory-based / in-context adaptation

Interpret feedback and memory changes as adaptation at the evaluated stage, with the update mechanism made explicit.

No reward-driven weight update

Supported claim scope

In-context adaptation or memory-based search under the stated task and evaluation conditions.

Stronger claims need more evidence

Reward-driven weight improvement, calibrated exploration, or safe persistent adaptation from memory feedback alone.

Claim tier
Non-RL stage comparator: memory / in-context adaptation.The manuscript includes these mechanisms in DPC reporting without making them a separate RL tier.
State or belief
Context and memory feedback.Report observed history, retrieved information, and memory lifetime; the manuscript does not supply a complete state specification.
Action granularity and horizon
Decisions conditioned on updated context or memory.Report the concrete action set, trial boundaries, termination, and horizon.
Reward and cost
Memory feedback described as "verbal reinforcement learning."The exact feedback source and cost channels are not specified here; report them for the evaluated implementation.
Prompt/task support
Not specified in the manuscript's boundary example.Report task distribution, environment conditions, and evaluation coverage.
Response/trajectory support
Trajectory and memory-history support.Report which histories inform adaptation and where unsupported behavior may occur.
Value and uncertainty
No calibrated uncertainty or value object specified here.If exploration or risk claims rely on one, report its target, estimator, and calibration.
Model interface
In-context adaptation or memory-based search.Report the search or context-update interface; memory feedback alone does not establish a learned transition model.
Adaptation surface
Context / memory change without a reward-driven weight update at this stage.Report retention and reset rules. Deleting memory and rolling back weights have different scopes.

Priority evidence checks

  • Context update rule and memory lifetime
  • Feedback source and evaluation distribution
  • Trajectory support, memory retention, and rollback scope where relevant
Manuscript basis: Review-relevant stage distinctions; alternative-view discussion.
Citation keys: shinn2023reflexion

Reading the adaptation field. Training-time policy fitting is separated from deployment updates. The manuscript allows a completion-only DPO card to mark deployment adaptation as not applicable; that does not mean the policy is unchanged during training. Action granularity and the horizon convention are also separate reporting choices.
